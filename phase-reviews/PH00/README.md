## Scope of this build

A single infrastructure room, generated by a small runtime C++ module, demonstrates a 152 cm Ivo-scale proxy, ash-blue clothing, a side camera, cool structural materials, dark foreground framing and a warm porcelain marker. Walk across a low step, bounded moving platform and Blender calibration tile to register contact. This is not a campaign location or a Hold implementation. Art and procedural limb movement are proxies, not final quality claims.

Enhanced Input maps keyboard and gamepad. Pause, restart, quit, temporary contact audio, mute and volume controls are present. Development HUD instructions are deliberately temporary. There are no dependencies on editor code in the runtime module. Python asset generation runs only in the editor.

## Reproduce

1. Install the locked engine and compiler components above. Engine content is supplied by the licensed Unreal installation, not this repository.
2. Clone the repository with Git LFS installed; run `git lfs pull`.
3. In the repository root run `powershell -ExecutionPolicy Bypass -File BuildScripts/Build-PH00.ps1`. Override `-EngineRoot` if needed.
4. Review `Builds/PH00/Windows/TheHeld.exe`. This packaged executable needs no running editor. Install the included prerequisites on a fresh Windows profile if needed.
5. Optional: pass `-CreateAssets` to rebuild foundation materials and reimport source assets. This updates generated assets; it is not necessary for a normal clone build.
6. Run `powershell -ExecutionPolicy Bypass -File BuildScripts/Test-PH00.ps1 -Width 1280 -Height 720`, then repeat with `-Width 1920 -Height 1080`. The script forces the actual resolution, checks fresh route results and validates PNG dimensions. Use `-BuildDirectory` to test another packaged Windows directory.

The script compiles editor and game targets explicitly with `-NoHotReloadFromIDE`, then cooks/stages/packages. This avoids interfering with Live Coding in the user's other open editor. Do not upgrade engine/plugins automatically. Do not include Binaries, Intermediate, Saved or derived caches in source control. Lock binary maps/Blender files before concurrent edits; one owner per binary asset.

## Controls and review route

| Action | Keyboard | Gamepad |
|---|---|---|
| Move | A / D or arrows | Left stick |
| Contact marker | E | A / bottom face button |
| Pause / resume | Esc | Menu |
| Restart room | R | Y / top face button |
| Mute / unmute | M | X / left face button |
| Volume | - / + | LB / RB |
| Quit while paused | Q | View |

Walk left and right; confirm screen direction. Cross the step, platform and tile. Contact from far away must fail; contact near the marker must succeed. Pause on the platform and verify both character and platform freeze; resume, restart and repeat. Check cue audibility and mute. Swap keyboard/controller during play. Inspect 720p and 1080p for silhouette and UI readability. This session is a quality review, not a puzzle-comprehension test.

## Physics and identity boundary

PH00 uses stock CharacterMovement collision/gravity and an analytically bounded 0–10 cm platform excursion. The full blueprint process clock, ownership and deterministic Hold machinery are not implemented. PH01 must integrate the lane controller with the project clock; PH02 introduces canonical Hold. CharacterMovement substepping alone cannot satisfy that contract.

Authored fixture actors use unique `PH00.*` tags. Do not persist generated Unreal actor names. Campaign semantic GUIDs and save ownership remain future phases. Asset generation validates required references, deliberately tests a missing reference, and checks the Blender tile before/after import at 100 × 100 × 12 cm. This is a basic validator, not the later campaign integrity suite.

## Research used

- [Epic: Packaging projects](https://dev.epicgames.com/documentation/en-us/unreal-engine/packaging-your-project): validate build, cook, stage and packaged launch separately. Explicitly cook the foundation assets and runtime primitive meshes because the room loads them dynamically.
- [Epic: Enhanced Input](https://dev.epicgames.com/documentation/en-us/unreal-engine/enhanced-input-in-unreal-engine): use actions and a mapping context, with the Enhanced Input player/input-component classes configured in DefaultInput.ini.
